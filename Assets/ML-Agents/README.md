# Training the ship agent

The `Base Level` scene is set up for ML-Agents PPO training. The ship observes its position, the three closest obstacles, and its health. It chooses horizontal and vertical movement and whether to fire. A bullet hit earns a small reward, destroying an asteroid earns a larger reward, a bullet that leaves the screen without hitting an asteroid gets a small penalty, and collisions and elapsed time are penalized. Destroying the ship ends the episode with a larger penalty.

## Start or continue training

`mlagents==1.1.0` requires Python **3.10.1 through 3.10.12**. Python 3.11+, and later 3.10 patch releases, are not accepted. Install Python 3.10.12 (64-bit), then check that the Python launcher selects it:

```powershell
py -3.10 --version
```

The output should be `Python 3.10.12`. If it shows another version, use the full path to the 3.10.12 `python.exe` instead; for example:

```powershell
& "C:\Path\To\Python31012\python.exe" -m venv .venv310
```

Create a fresh environment so it does not reuse the incompatible Python version from an earlier `.venv`:

```powershell
py -3.10 -m venv .venv310
.\.venv310\Scripts\python.exe --version
.\.venv310\Scripts\python.exe -m pip install "setuptools<81"
.\.venv310\Scripts\python.exe -m pip install mlagents==1.1.0
```

Confirm the environment reports Python 3.10.12 before installing.

From the project root, start training:

```powershell
.\.venv310\Scripts\mlagents-learn.exe Assets\ML-Agents\ship-agent.yaml --run-id=ship-v1
```

When prompted, open the project in Unity, open `Assets\Scenes\Base Level.unity`, and press Play. To save and stop, press `Ctrl+C` once and wait for the final model to be written under `results\ship-v1`.

To improve the same policy with more experience, run the same command again with `--resume`:

```powershell
.\.venv310\Scripts\mlagents-learn.exe Assets\ML-Agents\ship-agent.yaml --run-id=ship-v1 --resume
```

Use a new run ID to start over rather than continue the learned policy. Training checkpoints and TensorBoard summaries are kept in the `results` directory, which is generated by the trainer.

## Play with the trained model

In Unity, select the Player object in the `Base Level` scene and assign `results\ship-v1\ShipAgent.onnx` to the ML-Agents Behavior Parameters **Model** field. Keep the behavior name as `ShipAgent`. With no model assigned and no trainer connected, the agent uses its built-in non-random heuristic.

## Record model inference sessions

To evaluate a trained model without training, assign it to the Player's Behavior Parameters **Model** field and press Play in Unity. With the behavior type set to `Default` and no trainer connected, the agent runs local inference. The Editor records model-inference runs, not heuristic-only runs or sessions connected to a trainer.

When the model-controlled ship is destroyed during Editor Play mode, Play mode stops automatically and the report is saved. The inference run has no maximum episode-step limit, so reaching the training limit cannot reset the ship during a solo playthrough. Manually stopping Play mode also saves the report. It is written to `AgentPlaySessions.csv` in Unity's `Application.persistentDataPath`; the Console logs the full path. The CSV contains a row for each episode (survival time, asteroids destroyed, and whether the episode ended or Play mode was stopped) and a session summary (episode count, total survival time, and total asteroids destroyed). Survival time uses game time and does not increase while the game is paused. Reports from later Play sessions are appended to the same file. These changes apply only to model inference; during training, the configured maximum episode steps and normal episode resets remain unchanged.
